Нагрузочная проверка метрик worker pool ЛР3

Команда повторения: make test-position-pool-load
Зависимости: работающие компоненты environment.toml, .env, Go, Python 3, psql.
Скрипт создаёт собственную схему PostgreSQL, запускает отдельный экземпляр сервиса,
меняет задержку лабораторного Push Service на 5000 мс, затем возвращает её в 0.
Не запускайте проверку одновременно с другими тестами той же заглушки.
После завершения временная схема удаляется.

Параметры: 200 устаревших поездок, 4 воркера, канал ёмкостью 10,
проверка раз в 1 с, таймаут Push Service 1 с. Эти ускоренные параметры
используются только тестовым процессом; для обычного запуска действуют конфиги приложения.
Интервал экспорта метрик: 15 с. Метрики читаются из Prometheus.
Продолжительность успешного прогона: 49.50 с.
Экземпляр: positions-load-19c054ad08f44fb480a8e29e8e551638

Наблюдения при медленных пушах:
- queue.size = 6, workers.active = 4;
- stale_checks dropped = 1855;
- запросов Push Service с ошибкой = 36.

После остановки поступления задач и снятия задержки:
- queue.size = 0, workers.active = 0;
- success = 6, error = 60;
- positions.saved = 1;
- код выхода процесса = 0.

Проверок /ready: 52; максимальная задержка: 2.49 мс.
Наблюдавшийся RSS: 21.66–27.33 МиБ.
Это измерения одного короткого прогона, а не доказательство отсутствия утечек при любой нагрузке.

Gauge показывает снимок, а не максимум между сборами. Поэтому queue.size может
быть ниже ёмкости даже при растущем dropped. Отмена ожидающей задачи освобождает
запись дедупликации, а физическое место в канале — после чтения воркером.
Счётчики dropped и duplicate считают попытки на разных тиках, а не уникальные поездки.

Все исходные данные и PromQL: worker-pool-load.json.
График исходных данных: worker-pool-load.png (Gonum Plot).
Дашборд для импорта: deploy/grafana/positions.json.

В этой конфигурации Prometheus метка экземпляра приложения называется exported_instance;
обычный instance обозначает адрес коллектора. Скрипт позволяет изменить метку через --instance-label.
