### Проверка классификации инструмента

Gremlins v0.6.0 различает падение теста и ошибку сборки по коду завершения `go test`. В этом окружении ошибка компиляции тоже возвращает код 1 и оказывается в `KILLED`.

Четыре мутации `ARITHMETIC_BASE` отдельно воспроизведены через `go test -overlay`: замена строкового `+` на `-` даёт `invalid operation: operator - not defined`. Такие мутанты не проверяют силу ассертов:

| Файл | Строка:столбец | Исходное выражение |
|---|---|---|
| `internal/domain/trip/errors.go` | 17:17 | `e.Field + " "` |
| `internal/domain/trip/errors.go` | 17:23 | `e.Field + " " + e.Reason` |
| `internal/domain/trip/trip.go` | 80:40 | `field + ".latitude"` |
| `internal/domain/trip/trip.go` | 83:40 | `field + ".longitude"` |

С учётом этой проверки результаты **до и после одинаковы**: **34 сгенерированных, 30 компилируемых убиты тестами, 0 выживших, 4 некомпилируемых**. Среди компилируемых мутантов эффективность — 100%.

## Разбор

Выживших и непокрытых мутантов в обеих областях нет. Эквивалентных выживших, которые нужно было бы обосновывать или исключать, тоже нет. Новые тесты по результатам этого набора мутаций не понадобились.

Что проверялось:

| Изменение | Почему существующие тесты его обнаруживают |
|---|---|
| Проверки пустых UUID: `==` → `!=` | Есть успешное создание и отдельные случаи пустых `user_id` и `driver_id` |
| Цена: `< 0` → `<= 0` или `>= 0` | Есть отрицательная, положительная и нулевая цена |
| Координаты: сдвиг границы, инверсия сравнения, смена знака отрицательной границы | Есть точки на всех границах и вне диапазонов |
| Проверка координат: `||` → `&&` | Есть случаи, где нарушена только одна граница диапазона |
| Проверка статуса при завершении: `!=` → `==` | Проверяются завершение активной поездки и отказ без перезаписи времени для завершённой |
| Проверки ошибок в usecase: `!= nil` → `== nil` | Проверяются успех, ошибки репозиториев, истории и транзакций; проверяются возвращённая ошибка и отсутствие лишних вызовов |

Ограничения: 100% относится только к сгенерированным операторам. В частности, Gremlins v0.6.0 не генерирует удаление обычного вызова функции, замену аргумента-контекста или строковой константы. Поэтому этот результат не доказывает обнаружение удаления метрики, потери контекста транзакции или изменения причины в истории. Корректность конкурентных операций с БД проверяется отдельными интеграционными тестами, а не этим прогоном.

## Повторение

Из корня репозитория:

```bash
make test-mutation
```

Первый запуск устанавливает закреплённый Gremlins в `bin/gremlins/v0.6.0/` через `go install`; нужен доступ к Go module proxy. Зависимости инструмента не добавляются в `go.mod` сервиса. Отчёты повторного запуска сохраняются в игнорируемой папке `reports/mutation/latest/`, исторические `before/after` не перезаписываются.

Другую папку можно задать явно:

```bash
make test-mutation MUTATION_REPORT_DIR=reports/mutation/local-run
```

Для повторения исторического «до» нужен код и тесты указанной выше исходной ревизии с текущими Makefile и `.gremlins.yaml`. Прогон по будущей версии кода может дать другие результаты. Порог метрики не задан: новые выжившие мутанты следует разбирать, включая возможную эквивалентность.
